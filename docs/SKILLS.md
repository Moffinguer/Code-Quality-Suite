# Skills, recipe book and the Junta norms map

The AI layer of a repository is three folders that every agent (Claude Code, OpenCode, Codex)
reads. `scripts/ai-init.sh <repo>` creates them from `ai-template/`; existing files are kept.

| Folder | What | Read by |
| --- | --- | --- |
| `AGENTS.md` (+ `CLAUDE.md`, `GEMINI.md` importing it) | rules that always apply, roles, where things are | all agents |
| `.agents/skills/<name>/SKILL.md` | skills: procedures loaded on demand by their `description` | OpenCode, Codex; Claude Code through the copy in `.claude/skills/` (`scripts/ai-sync.sh`) |
| `.claude/agents/*.md` | roles as subagents (model per role) | Claude Code; OpenCode through `.opencode/agents/`, generated by `ai-sync.sh` with the gateway roles |
| `knowledge/` | the project's memory: Junta norms, recipes' assets, lessons, decisions | all agents (and Obsidian / Basic Memory) |

## Skills shipped in the template

| Skill | Use |
| --- | --- |
| `jda-norms` | before designing, coding or reviewing: which Junta norms apply and what they require |
| `jda-ingest` | a new Junta notification or guideline arrives: split it into norm notes, update the map, propose gate rules |
| `quality-gate` | run `scripts/qs-run.sh` on edited files and fix the findings |
| `branch-workflow` | branch names, `git np / nr / subir / integra`, ASCII commits |
| `norms-review` | review a diff against the norms, the gate and the spec |
| `lessons-learned` | record what went wrong so the next agent does not repeat it |
| `recipe-template` | copy it to create a recipe of your own (not loaded automatically) |
| `recipe-technical-doc` | example recipe: technical document of an OT in the team's format |

## How the Junta knowledge map works

```text
Junta notification (PDF, DOCX, e-mail)
   -> knowledge/jda/inbox/                     you drop it there
   -> "ingest the inbox" (skill jda-ingest)    agent extracts atomic rules
   -> knowledge/jda/norms/<area>-<name>.md     one note per rule: id, quoted text, status,
                                               applies_to, source, date, supersedes, check
   -> knowledge/jda/INDEX.md                   topic -> norms -> enforced by
   -> knowledge/jda/proposals/<date>.md        rule changes for .quality-rules.json (you approve)
   -> every later task: skill jda-norms        checklist of applicable norms, cited in commits
```

The `check` field closes the loop: a norm a tool can verify becomes a rule in
`.quality-rules.json` (Checkstyle, PMD, encoding, branch policy...), so it is enforced on every
commit instead of depending on an agent remembering it. Norms that need judgement
(`check: manual: ...`) are what the `reviewer` role verifies.

## Your recipe book

A recipe is a skill: copy `.agents/skills/recipe-template/` to `.agents/skills/recipe-<name>/`,
write the steps (exact commands, templates in `knowledge/recipes/`), the checks before
finishing, and a precise `description` (agents choose skills by it). Then
`bash <suite>/scripts/ai-sync.sh`. Examples worth writing first: "create the design document
of an OT", "prepare a delivery (scripts, release notes, tag)", "validate a PL/SQL package
before delivery", "accessibility check of a JSP page".

## Community skills worth adding

Install them per repository (or per user) and keep only what you use; every skill costs
context when its description is listed.

| Source | What | Notes |
| --- | --- | --- |
| [anthropics/skills](https://github.com/anthropics/skills) | official: docx, pdf, xlsx, pptx, skill-creator... | `skill-creator` helps write and test your own recipes |
| [obra/superpowers](https://github.com/obra/superpowers) | TDD, systematic debugging, brainstorming, plan/execute | a full working method; adopt pieces, it is opinionated |
| [EveryInc/compound-engineering-plugin](https://github.com/EveryInc/compound-engineering-plugin) | plan -> work -> review -> compound (lessons) | the same loop as `lessons-learned`, more complete |
| [skills.sh / Vercel skills CLI](https://skills.sh/docs/cli) | `npx skills add <repo>` installs skills for several agents at once | handy to install community skills into `.agents/skills` |

With the suite: `bash <suite>/scripts/ai-skills.sh list anthropics/skills`, then
`ai-skills.sh add anthropics/skills skill-creator` (copied into `.agents/skills` and
`.claude/skills`, pinned to the commit in a `.source` file); `ai-skills.sh installed` lists them.

Review a community skill before installing it: a skill can run commands. Prefer pinning a
commit or tag when copying it into the repository.
