# Languages and tools

Generated by `tools/gen.py` from `registry/src/` (184 languages, 324 tool entries). Do not edit `LANGUAGES.md` by hand:
edit the catalog and run `python3 tools/gen.py`.

## Quality levels

Levels are cumulative. Set them in `.quality-rules.json` (`level` at the top, or per language).

| Level | What runs |
| --- | --- |
| `off` | nothing (the language is ignored) |
| `syntax` | syntax checks only (native parser, or the built-in check) |
| `format` | + identifying mark (shebang/modeline) + the formatter |
| `standard` (default) | + linters |
| `strict` | + deep analysis (type checkers, security, complexity, spelling) |

## No-clash policy

- **One formatter per file type.** Every language has exactly one formatter (or the built-in safe
  one), so two tools never fight over layout.
- **Linters never judge layout the formatter owns.** Their layout rules are disabled in the base
  rules (yamllint `document-start`, detekt `MaxLineLength`, SwiftLint style rules, luacheck line
  length, Solhint `quotes`, PSScriptAnalyzer formatting rules, gherkin-lint `indentation`, ...).
  When a linter and its formatter share a config (Ruff, RuboCop, SQLFluff, djLint, markdownlint,
  vsg, npm-groovy-lint, dotenv-linter) the linter *inherits* the formatter's settings, so line
  length and indentation can only be set once.
- **Deep tools are semantic only** (types, security, complexity), never style.
- **Subtypes refine, they do not add a second formatter.** A GitHub workflow is still YAML
  (yamlfmt) plus actionlint and zizmor; a Helm/Jinja-templated YAML file is not parsed as YAML.
- **Ambiguous extensions** (`.h`, `.m`, `.pl`, `.v`, `.cls`, `.sh`, `.conf`, `.inc`, `.pp`, `.ts`,
  `.cl`) are resolved by content probes; when the probe is confident the commit adds an editor
  modeline (or shebang) so the next run does not have to guess.
- **Built-in fallbacks.** A language without a syntax tool gets the built-in check (encoding,
  NUL bytes, conflict markers, bracket balance outside strings/comments). A language without a
  formatter gets the built-in safe formatting (trailing whitespace and the final newline only;
  line endings, BOM, multi-line strings, heredocs and backslash continuations are preserved).
  Formats where whitespace is content (`.properties`, CSV/TSV, Markdown, ignore files, JSONL)
  are never reformatted.

## Opt-in tools

Tools marked **(opt-in)** are heavy (Emacs, Mermaid, LLVM, the Go toolchain...), noisy on legacy
code, or rewrite more than layout. They are listed in the language's section of
`.quality-rules.json` with `"enabled": false`. Set it to `true` and the next commit installs the
tool (one more image layer) and runs it; until then the built-in fallback covers that role.

## Not included (and why)

Tools that need a server or a cloud account (SonarQube, Snyk, Codacy, DeepSource, Qodana) and
CodeQL (licence restricts use on non-open-source code) are out of scope for now: the suite only
runs local tools, offline. Candidates per language, waiting for a reliable offline distribution:

- **ActionScript**: Apache Royale linter.jar / formatter.jar (Allman/tab style rewrites AS3 code)
- **Apache httpd config**: apache2 -t on a generated wrapper (false positives on missing certificates/paths)
- **AWK**: gawk --pretty-print (moves comments)
- **C#**: dotnet format style/analyzers (needs the project to restore and build)
- **Coq / Rocq**: coqc -vos (~1.15 GB; writes .vo next to sources)
- **D**: D-Scanner / dfmt (no release binaries; ~4 min build with LDC); ldc2 -o- (186 MB, opt-in deep check)
- **ERB (Ruby templates)**: erb_lint (gem); htmlbeautifier (gem)
- **Forth**: gforth can only run files (no parse-only mode); executing them is unsafe
- **Generic .conf**: a bare .conf has no dialect; apache/nginx files are detected by content
- **Godot scenes/resources**: godot --headless ResourceLoader (146 MB engine + a staged project)
- **Graphviz DOT**: dot -Tcanon (drops comments)
- **Haxe**: haxe --no-output (type-checks: needs the class path and haxelib libraries); haxe-formatter / haxe-checkstyle (no binaries; haxelib server unreachable offline)
- **HCL (Packer, Nomad, Terragrunt, ...)**: hclfmt; packer fmt
- **HLSL**: DXC (reference compiler; 515 MB download, amd64)
- **Idris**: Idris 2 has no packages or binaries for Ubuntu 24.04
- **Ignore / attribute lists**: codeowners-validator (CODEOWNERS only); git ignores malformed lines silently
- **JSP**: Jasper JspC translation (strongest JSP check; needs every taglib jar of the project)
- **Lean**: lean 4 (3 GB toolchain; elaboration runs #eval)
- **Mermaid**: mermaid-cli (renders; needs headless Chromium, ~400 MB)
- **Nix**: statix; deadnix (no prebuilt binaries outside Nix)
- **OCaml**: ocamlformat (opam only; needs a per-project .ocamlformat)
- **Odin**: odin check -vet (~170 MB compiler)
- **Plain text**: plain text: encoding, conflict markers and safe whitespace are the checks
- **Racket**: raco fmt (needs Racket)
- **Razor**: no offline CLI: the Razor compiler runs only inside a dotnet build with a NuGet restore
- **ReasonML / ReScript**: refmt for .re/.rei (Reason 3.6, unmaintained, x64 only)
- **Scala**: scalafix (needs a SemanticDB build)
- **Smalltalk**: GNU Smalltalk is not packaged for Ubuntu 24.04; Pharo/Squeak need a VM image
- **Textile / wiki markup**: pandoc reader (158 MB; catches only gross MediaWiki errors)
- **VBA / VB6**: vba-linter 0.0.x (needs files staged in a directory; flags every LF line ending)
- **WGSL**: naga-cli (validator; cargo build, no release binaries); no safe formatter: @wasm-fmt/wgslfmt corrupted shaders in tests
